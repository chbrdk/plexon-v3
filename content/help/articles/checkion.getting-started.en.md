# CHECKION in five checks

CHECKION does not treat a URL as an isolated test case. Scans belong to a **Collection** — the shared workspace for every later WCAG, SEO, and GEO run.

This article is the short path from first page to GEO presence. Use authorized demo domains only; never crawl a customer site without permission.

## Recommended order

1. **WCAG quick** — one page, fastest signal.
2. **WCAG deep** — same host as a light corpus; spot systemic issues.
3. **SEO crawl** — coverage of titles, meta, headings across the corpus.
4. **GEO Model memory** — ungrounded brand presence in model answers (separate from Live search).

Chain: **page → corpus → findability → GEO presence**.

## Rules that never change

- CHECKION’s “project” is the local capability record for the same PLEXON Collection — not a second project type.
- Jobs are **async**: Launch queues work; open **Jobs** and wait for Completed before interpreting scores.
- Queued, Running, Paused, Completed, and Failed must be named honestly — no success fiction.
- GEO **Model memory** and **Live search** are separate jobs; never merge hit rates.
