# CHECKION in fünf Prüfungen

CHECKION behandelt eine URL nicht als isolierten Testfall. Scans gehören zu einer **Collection** — dem gemeinsamen Arbeitsraum für spätere WCAG-, SEO- und GEO-Läufe.

Dieser Artikel ist der kurze Weg von der ersten Seite zur GEO-Präsenz. Nur freigegebene Demo-Domains nutzen; Kundenseiten nie ohne Erlaubnis crawlen.

## Sinnvolle Reihenfolge

1. **WCAG Quick** — eine Seite, schnellstes Signal.
2. **WCAG Deep** — denselben Host als leichten Corpus; systemische Issues finden.
3. **SEO-Crawl** — Abdeckung von Titeln, Meta, Überschriften im Corpus.
4. **GEO Model Memory** — ungestützte Markenpräsenz in Modellantworten (getrennt von Live Search).

Kette: **Seite → Corpus → Findability → GEO-Präsenz**.

## Regeln, die gelten bleiben

- Das CHECKION-„Project“ ist der lokale Capability-Datensatz derselben PLEXON Collection — kein zweites Projektmodell.
- Jobs sind **asynchron**: Launch stellt Arbeit in die Warteschlange; unter **Jobs** auf Completed warten, bevor Scores interpretiert werden.
- Queued, Running, Paused, Completed und Failed ehrlich benennen — keine Erfolgsfiktion.
- GEO **Model Memory** und **Live Search** sind getrennte Jobs; Trefferquoten nie vermischen.
