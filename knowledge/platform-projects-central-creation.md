# Collection projects (PLEXON) — central creation

**Product model:** `specs/domain/collection-projects.md` (Accepted — Collection = sole user-facing project).

- **Source of truth:** `platform_projects` in PLEXON, scoped under a **Company**. User language: **Projekt / Collection** — not “platform vs product project types.”
- **Mirrors (capabilities):** CHECKION, AUDION, and BRANDION keep local `projects` rows with `platform_project_id`, created/updated via **service provisioning** (`PUT .../platform/provisioning/projects/{id}`).
- **Create invariant (1A):** Every **new** Collection always gets binding placeholders for **checkion**, **audion**, and **brandion**, then syncs them (brandion when `NEXT_PUBLIC_BRANDION_URL` / `BRANDION_API_URL` is set). A failed product sync is `pending`/`failed` on that capability — not a finished product-only project.
- **AUDION-first origin:** AUDION may create locally, then call `POST /api/platform/provisioning/audion-project-origin` (Body: `audionProjectId`, `name`, `domain?`, optional `ownerPlexonUserId` / `platformCompanyId`). When owner/company are omitted, Plexon **auto-resolves** (prefer existing company membership) or **bootstraps** a Federation home user/company. PLEXON creates `platform_projects`, binds the existing **AUDION** UUID, and syncs **CHECKION** (+ **BRANDION** best-effort). Idempotent calls repair missing CHECKION. AUDION env: `PLEXON_API_BASE_URL` (or `PLEXON_AUTH_URL`), `PLEXON_SERVICE_SECRET`.
- **CHECKION-first origin:** Same pattern via `POST /api/platform/provisioning/checkion-project-origin` — owner/company optional under service secret. CHECKION env: `NEXT_PLEXON_BASE_URL`, `PLEXON_SERVICE_SECRET`, `CHECKION_FEDERATION_MODE=live`.
- **BRANDION-first origin:** `POST /api/platform/provisioning/brandion-project-origin` (Body: `brandionProjectId`, `name`, `domain?`, optional owner/company). Binds BRANDION and best-effort syncs CHECKION + AUDION. BRANDION env: `NEXT_PLEXON_BASE_URL`, `PLEXON_SERVICE_SECRET`, `BRANDION_FEDERATION_MODE=live`.
- **Create APIs (Phase 1):** Admin and platform company project POST always `ensureBindingPlaceholders` then `syncPlatformProjectToProducts` for **checkion / audion / brandion**.
- **Canonical hub UX:** Nav **Projekte** → `/projects` (list + create). Home shows a short insights preview linking to the hub. Detail: `/projects/[id]`.
- **Access:** `user_platform_project_assignments` (PLEXON) expands into product-local `projectAssignments` when bindings have `external_project_id`. Dashboard **“Your projects”** lists **Collections only** (v3 fresh start — no product-only insight cards).
- **Fresh start:** plexon-v3 and companion product databases are new islands. **No** legacy backfill from old product-only projects (`migrate-msqdx-platform-projects.md` is historical for other environments, not a v3 requirement).
- **Dashboard API:** `GET /api/platform/projects/{id}/dashboard` (session) aggregates CHECKION/AUDION with service headers incl. `X-Plexon-User-Id`.
- **Open-AUDION links:** Dashboard and `GET /api/platform/me/project-insights` set AUDION admin URL with `platformProjectHint` (when AUDION summary exists) and always **`platformCompanyId`** (`platform_projects.company_id`). Builder: `lib/audion-admin-launch-url.ts`.
- **Federation contract:** `2026-05-plexon-federation-v3` (project upsert + summary GET).
- **Knowledge Pack:** Collection-scoped shared brief (facets) is **not** part of thin upsert. CRUD via dedicated knowledge endpoints — `specs/domain/collection-knowledge-pack.md` · `specs/api/collection-knowledge-pack.md`. Companions: Audion publish, Checkion GEO consume.
