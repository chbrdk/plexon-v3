# PLEXON Suite Tutorialprogramm

## Ziel

Das Tutorialprogramm erklärt PLEXON als zusammenhängende Suite: Eine Collection bündelt den Arbeitskontext, die Produkt-Apps liefern spezialisierte Fähigkeiten und der PLEXON Assistant unterstützt appübergreifend.

Tutorials vermitteln deshalb keine voneinander getrennten Produkt-Projekte. Bezeichnungen wie **Project** in einzelnen aktuellen Oberflächen werden als lokaler Capability-Datensatz einer **Collection** eingeordnet.

## Formatmodell

| Format | Dauer | Ergebnis |
|---|---:|---|
| Quick Start | 2–5 Minuten | Ein sichtbares erstes Ergebnis ohne Vorwissen |
| Kernworkflow | 8–15 Minuten | Ein vollständiger fachlicher Ablauf |
| Deep Dive | 15–30 Minuten | Auswertung, Varianten und fortgeschrittene Entscheidungen |
| Suite Journey | 12–25 Minuten | Übergabe zwischen mindestens zwei Apps innerhalb einer Collection |

Jedes Tutorial erhält:

- ID, Zielgruppe, Lernziel und Erfolgskriterium
- Voraussetzungen und kontrollierte Beispieldaten
- exakten Klickpfad anhand der aktuellen Oberfläche
- Sprechertext, Bildschirmregie und Einblendungen
- erwartete Zustände und Fehlerpfade
- Kennzeichnung von Live-, Demo-, Fixture- und geplanten Funktionen
- Produktions- und QA-Checkliste

## Produktionsreihenfolge

### Welle 1 — einfache, stabile Erfolge

1. CHK-QS-01 — Neue Collection für CHECKION anlegen
2. CHK-QS-02 — Ersten WCAG-Scan starten
3. CHK-CORE-02 — Komplette Domain untersuchen
4. CHK-CORE-03 — SEO-Abdeckung einer Domain prüfen
5. CHK-CORE-04 — GEO Model Memory messen
6. BRN-QS-01 — Datei im Detection Lab untersuchen
7. ECH-QS-01 — Tagespuls lesen
8. CRT-QS-01 — Collection und Composition öffnen
9. AUD-QS-01 — Easy Setup, sobald Demo/API-Zustand eindeutig ist

### Welle 2 — fachliche Kernworkflows

CHECKION Scan-Auswertung, BRANDION Evaluate, ECHON Briefing, AUDION Journey/Study und CREATION Editor.

### Welle 3 — Suite-Nutzen

Event Quick Check und die appübergreifenden Collection Journeys. Erst hier wird die vollständige Suite-Erzählung prominent ausgespielt.

## Wahrheits- und Freigaberegeln

Vor Veröffentlichung muss jedes Tutorial auf der Zielumgebung erneut durchgeklickt werden.

- **Live:** Ergebnis wird tatsächlich erzeugt und dauerhaft gespeichert.
- **Demo:** Ablauf funktioniert, verwendet aber kontrollierte Beispieldaten.
- **Fixture:** Gezeigtes Ergebnis ist vorproduziert und muss so bezeichnet werden.
- **Geplant:** Darf nur als Vorschau oder Roadmap erscheinen, nicht als Anleitung.
- Produkttexte in PLEXON werden nicht ungeprüft übernommen, wenn sie dem aktuellen App-Stand widersprechen.
- Ein CHECKION/AUDION/BRANDION/CREATION „Project“ wird im Tutorial immer als Capability-Datensatz einer Collection erklärt.
